# Decision

* [A degraded Phase-2 step contributes a finding, never flips a boolean](degraded-steps-contribute-findings.md) - Every degrading Phase-2 step must add a finding the verdict can read rather than silently reverting to a default, because findings are the only thing deriveCheckConclusion reads; the publish-validation crash path enforces this, the remaining steps do not yet.
* [Check for an existing attestation before writing a new one](idempotent-attestation.md) - Before signing a fresh SLSA provenance or CycloneDX SBOM attestation, probe the GitHub attestation store for the subject digest and reuse an existing URL rather than writing a duplicate.
* [Commits via the Git Data API, branch linking via GitBranch.createLinked](api-commits.md) - Release-branch commits are created through the Git Data API rather than git push, and branch-to-issue linking uses GitBranch.createLinked, the one operation with no REST equivalent.
* [Disable the persistLocal composite action and its act smoke loop](no-local-composite-action.md) - action.config.ts sets persistLocal.enabled to false, so no `.github/actions/local` composite is emitted and act-test.yml is gone; re-enabling it is a deliberate decision to start using act, not a default to restore.
* [Effect layers, not mocks, as the test-double mechanism](effect-layers-not-mocks.md) - Substitute in-memory Effect layers for every service dependency, stub unexercised members with Effect.die, and use a spawner seam plus @effected/memfs rather than a permissive command map or a stubbed filesystem noop.
* [Manifest sync guards need three independent legs, not two](three-legged-manifest-guards.md) - The action.yml manifest, the NAMES tuples in src/schema/*, and what src/ actually reads and writes are three independent sources of truth; a two-way check lets the third drift silently.
* [Never write process.env.GITHUB_TOKEN persistently](never-set-github-token.md) - Credentials travel as Redacted values through ActionState and pickToken rather than through the process environment; the one scoped, restored exception is Phase-1 native versioning, which never touches a registry or OIDC.
* [No test lives under src/ — one location plus a mirrored unit/ subtree](move-colocated-tests.md) - Every test lives at or below __test__/, mirroring source paths under __test__/unit/, with a placement guard making the rule executable instead of a convention nobody could state.
* [OIDC-first publishing, with token auth as bootstrap and fallback](oidc-first-authentication.md) - npm and JSR publish over OIDC trusted publishing by default; a token is used only to bootstrap a first-time npm publish, to retry once after an OIDC 404, or unconditionally for GitHub Packages, which cannot do OIDC at all.
* [Pack the tarball once per build directory, not once per target](pack-once-per-directory.md) - publishDirectoryGroup packs a directory's tarball once and reuses it for every registry target in that byte-group, then probes each target's registry to decide publish, skip, or abort before attesting the group once.
* [Phase 3 is six gated steps, target resolution ahead of the build gate](six-step-phase-3.md) - Phase-3 publishing runs detect, plan, build-and-SBOM, publish, releases and summary as six sequential gates, with target resolution deliberately placed before the build gate because it cannot fail.
* [Pin known-wrong behaviour with characterization tests before fixing it](characterization-first.md) - A test pinning a known bug is written to fail when the fix lands, named to the issue it pins, and converted rather than deleted once the fix ships.
* [Pin the npm publish CLI to 11.x via the package manager's dlx launcher](pin-npm-11.md) - Run every npm publish/pack invocation through the detected package manager's dlx launcher pinned to npm@11 rather than the runner's bundled npm, so OIDC trusted publishing works and npm 12's pack/publish breakage is avoided.
* [Recreate the release branch from main rather than rebase](recreate-not-rebase.md) - update-release-branch.ts recreates the release branch from main on every update instead of rebasing it, and treats a no-op version as a terminal "nothing to release" state.
* [Remove skip-token-revoke, pr-title-prefix, version-command, and the dead build-command read](removed-inputs.md) - action.yml carries none of skip-token-revoke, pr-title-prefix, version-command, or build-command; each was removed because it bought nothing, never reached a real title, was replaced by native versioning, or was read by nothing in src/.
* [Replace @actions/attest with the kit's sign/store split, assembled locally](replace-actions-attest.md) - @actions/attest was dropped for a bundler-incompatible dependency chain, an opaque failure surface, and a private coupling to the @actions/ environment; the kit splits signing from storage and this repo owns the one-place assembly in attest-helpers.ts.
* [Silk publishability rules invert the private flag and live upstream](silk-publishability-rules.md) - Silk-mode publishability is derived from publishConfig with the private flag as a last-resort default, inverting the @effected/workspaces vanilla default; the rules live in silk-effects and every phase resolves through one ignore-aware adaptive detector.
* [Three-phase workflow](three-phase-workflow.md) - Split the release into branch-management, validation, and publishing phases, each triggered by a distinct GitHub event, plus a 3a close-issues phase.
* [Version natively via the bundled silk-effects ReleasePlanner](native-versioning.md) - Phase 1 versions in-process through the bundled silk-effects ReleasePlanner instead of shelling out to a consumer ci:version script, making Phase 1 zero-install.
* [Version the output JSON Schema under its own path per release](versioned-output-schema.md) - The output document lives under a per-version path, schemas/5.0.0/silk-release-action-5.0.0.json today, and is referenced by $schema/$id in every payload, so an old payload's URL keeps resolving to the shape it was written against; the input schema stays unversioned at the repo root.
* [main.ts as guard, program.ts as composition, steps/ per phase body](program-steps-split.md) - main.ts is a 19-line entry guard, program.ts holds only composition, and each phase body is one module under steps/ with a declared failure posture.
